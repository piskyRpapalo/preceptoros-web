## What was built

**One face: an AI chatbot with a joystick, the same in web and app, with one element that changes (the palette).**

- `docs/rebuild/examples/face.js` + `face.css`: the shared product. `skins.json` holds the only per-skin difference: role → band name. `tools/face.tpl.html` + `tools/build.mjs` generate `basic.html`, `atlantis.html` and `zombie.html`. The pages are generated, so they cannot drift (the validator checks byte equality with the template).
- **Drawing (bubble/1, Intro grammar):**
  - The **base-crab is its own Fourier series**: `[[1,30,18,0],[5,5,5,32],[-3,5,5,-32]]`, which is r = R + a·cos(4u+π) written in house harmonics. It has four soft lobes (claws and legs), eyes from `arcs`, and no sprite.
  - The **node-stars** are the canonical star wave `[[1,R,R,0],[-4,.3R,.3R,0]]`.
  - The **preceptor-head** is the chat avatar (own frame).
  - The joystick is a Bubble frame too (ring `arcs` + knob `blob`). No CSS-drawn shapes.
- **Interaction:** the joystick (pointer drag/tap, arrow keys) walks the crab along five stops. Four stops hold stars. Arriving lights the star (band change plus `sc` 1.4 as the non-colour cue) and the Preceptor answers in the chat. The star buttons are the direct path (≥48 px). Movement is born only from input: no clock, no randomness.
- **Four channels:**
  - eye (canvas);
  - text (`aria-live` narration plus the live frame in `#packet` and the Machine view);
  - ear (Sound toggle, off by default; arrival plays `AtlasSintesis.vozDe({armonicos: star h})` → `suena`, then a `pop` separator: broadcast first, then the tail);
  - touch (`navigator.vibrate`, or NO_DATA with cause).
  - "Read aloud" uses only local English voices, or prints NO_DATA with cause.
- **Three audiences:**
  - Kids: one plain line ("Walk the crab to a star").
  - Technical readers: folded "Technical details".
  - **AIs:** `window.preceptorFace.state()/act(name)`, actions listed, every control labelled, the frame always beside the art.
- **Layout:** text left, art right on wide screens. On phones: header, art, joystick + stars, chat. The text never covers the art.
- **App:** `/` now serves the face (`interface/face/basic.html`); `/face/{skin}.html` serves each skin. The nine Bubble pieces are copied byte-for-byte from WEB `public/game/` and pinned by sha256 in `test_face.py`. The offline shell `sw.js` is v107 and precaches all of them.

## Findings (method, not verdicts)

1. **Luna's terrain harness painted nothing in a browser.** Script order loaded `comic_tokens` before `tabla_semantica`, and `valores.js` was missing, so the page said `NO_DATA · AtlasComicAtoms is not defined`. The old validator only ran in Node, so it stayed green. The new pages load the dependencies in order, and each skin was screenshotted and read before any claim.
2. **`style:"clear"` in `bubble_light.js` drops the body fill.** Only the cast shadow and the outline are painted, so filled shapes render as solid ink. The spec sentence "clear keeps the cast shadow and the outline only" matches the code but surprises any author. The face uses `volume`. Proposal (no change made): spell out in `docs/bubble-language.md` that `clear` is outline-only, or add the fill.
3. **Bestiary words hard-code their bands** (`crab`, `star` and `bust` use `cyan`/`ink`), so a skin cannot recolour them. The face composes the Intro anchors from primitives with the same proportions. **Proposal for FIRMO:** bubble/2 lets words take `f`/`s` overrides.
4. **`volume` decorations depend on the band family.** Highlights exist only for accent and seal bands, and the rim is always `cyan`. The geometry check therefore excludes `highlight`-tagged strokes; everything else is compared byte-for-byte.
5. **Playwright MCP was not connected (NO_DATA).** The local library plus the installed headless shell became the browser eyes (`tools/shoot.mjs`). The rack Android's Chrome is drivable through `adb forward tcp:9333 localabstract:chrome_devtools_remote` (`tools/android.mjs`): measuring layout, state and voices on the device itself is now one command.
6. **App guards, adjusted with the reason written next to each change:**
   - `test_herencia_web` and the G2 interface audit skip `interface/face/bubble/`: it is the web's code, pinned by sha in `test_face`.
   - G2 admits `NO_DATA` and `STALE`: the honest value and seal bands, not policy names.
   - The face constants were renamed to lowerCamel so they do not read as policy IDs.
7. **Deviation:** the old dashboard is still reachable at `/dashboard.html`. The model chat, voice and consola live there, and many app tests read it. Retiring it is the next piece. The face's free-text reply is NO_DATA until a model route is wired; the web must not `fetch`, so the wiring belongs to the app adapter, not to `face.js`.
8. The rack trail lines (telemetry, optimizations, pupil space) were written as files in the shared `p0x` tree and **not committed**. That tree is on `master` with 118 changes from other sessions, and committing there would carry them.
